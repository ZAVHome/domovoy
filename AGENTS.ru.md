# Правила работы с репозиторием

## О проекте

«Домовой» — заготовка Telegram-бота для сбора обращений жителей по работе управляющей компании. Предполагаемый сценарий: житель начинает заявку в настроенной группе дома и продолжает в личном чате с ботом; контекст дома передаётся через deep link.

Сейчас поддерживается полный текстовый сценарий заявок:

- `/report` в настроенной группе создаёт ссылку на личный чат и запускает мастер заявки.
- Бот собирает необязательные данные профиля и настроенные текстовые поля; заявка сохраняется после подтверждения.
- Житель постранично просматривает только свои заявки командой `/my_reports`.
- Ответственные из JSON обрабатывают заявки назначенных домов через `/reports`; администратор видит все дома.
- Статусы и история сохраняются, отправляются уведомления ответственным и жителям.

Приём фото/видео, управление конфигурацией из бота и восстановление незавершённого FSM после перезапуска не реализованы. Тексты бота на русском, идентификаторы и комментарии в коде — на английском.

- Ведите документацию проекта на русском и английском языках.
- Синхронизируйте русскую и английскую версии при каждом обновлении.

Храните план и краткий отчёт о выполнении на русском и английском: `plan.md`, `plan.ru.md`, `completion.md`, `completion.ru.md`.
- В план включайте цель, границы работ, этапы реализации и критерии готовности. В отчёте кратко перечисляйте сделанное, проверки и известные ограничения или последующие задачи.

## Технологии

- Python 3.11 или новее.
- aiogram `>=3.32,<4`, long polling без webhook.
- python-dotenv `>=1.0,<2` для загрузки корневого `.env`.
- SQLite через стандартный модуль Python `sqlite3`.
- setuptools и структура пакета `src/`, настройка поиска пакетов находится в `pyproject.toml`.

В репозитории пока нет lock-файла, веб-фреймворка, внешней БД, системы миграций, очереди задач и контейнерной конфигурации.

## Структура и назначение модулей

- `pyproject.toml` — метаданные пакета, версия Python, зависимости и настройки setuptools.
- `src/domovoy/__main__.py` — точка входа: загружает настройки, инициализирует БД, создаёт `Bot` и `Dispatcher`, подключает router и запускает long polling. `settings` передаётся в `start_polling` для внедрения в обработчики.
- `src/domovoy/config.py` — настройки окружения, загрузка JSON и проверка конфигурации при старте.
- `src/domovoy/database.py` — схема SQLite и аддитивные миграции, включая идемпотентность создания заявки.
- `src/domovoy/repository.py` — параметризованные операции SQLite, постраничные выборки с проверкой доступа, транзакционное создание заявки и атомарное сравнение статуса.
- `src/domovoy/states.py` — состояния мастера заявки; состояние хранится в памяти и теряется после перезапуска.
- `src/domovoy/handlers.py` — мастер заявки, просмотр, обработка ответственными, статусы и уведомления.
- `src/domovoy/__init__.py` — только docstring пакета.
- `config/` — безопасные примеры JSON для домов, классификатора, статусов и ответственных.
- `artifacts/` — планы работ и краткие отчёты на русском и английском в последовательно нумеруемых папках, например `001-text-report-mvp/`.
- `.env.example` — шаблон переменных окружения.
- `README.md` и `README.ru.md` — синхронные инструкции на английском и русском.

## Установка и запуск

Работайте из корня репозитория:

```sh
python -m venv .venv
source .venv/bin/activate
pip install -e .
cp .env.example .env
```

Укажите в `.env` `BOT_TOKEN` и числовой `ADMIN_TELEGRAM_ID`. Замените пример ID группы и адрес в `config/houses.json`; остальные JSON-файлы настройте по необходимости. Добавьте бота в группу и запустите:

```sh
python -m domovoy
```

Команда `/report` в группе должна прислать ссылку на личный чат. Для реальной работы нужны действительные Telegram credentials и доступ к Telegram API.

`PROJECT_ROOT` вычисляется из `src/domovoy/config.py`, а `CONFIG_DIR` всегда указывает на `<корень проекта>/config`. `DATABASE_PATH` по умолчанию равен `./data/domovoy.sqlite3`; относительный путь считается от корня проекта. Инициализация создаёт каталоги и применяет миграции. Дома, категории, статусы и назначения ответственных остаются в JSON и проверяются при старте, но не копируются в БД.

## Конфиги

Переменные окружения:

- `BOT_TOKEN` — обязателен; при отсутствии запуск завершается с `RuntimeError`.
- `ADMIN_TELEGRAM_ID` — обязателен, только десятичные цифры. Пока используется для приветствия администратора в `/start`, а не для выдачи роли в БД.
- `DATABASE_PATH` — необязательный путь к SQLite, по умолчанию `./data/domovoy.sqlite3`.

JSON:

- `config/houses.json` — `chats` связывает точный Telegram ID группы с ID дома и адресом.
- `config/classification.json` — `locations`, категории и текстовые поля; поле с ID `description` хранится как описание заявки.
- `config/statuses.json` — статусы в порядке `new`, `in_progress`, `resolved`, `closed`; только `new` отмечен начальным.
- `config/responders.json` — `assignments` связывает настроенный `house_id` с положительными Telegram ID ответственных.

JSON проверяется при старте, включая ссылки назначений на настроенные дома. Интерфейса конфигурации в боте нет: для изменений редактируйте JSON и перезапустите процесс.

## Стиль кода

Используйте четыре пробела, понятные имена модулей и функций, аннотации типов у публичных функций и настроек, `pathlib.Path` для путей и абсолютные импорты `domovoy.*`. Telegram-обработчики — асинхронные функции в общем `Router`. Пользовательские сообщения оставляйте на русском, если язык продукта намеренно не меняется.

JSON-примеры форматируйте двумя пробелами; используйте только вымышленные ID, адреса и токены. В `pyproject.toml` не настроены форматтер или линтер; не заявляйте, что конкретный инструмент обязателен, пока он не добавлен.

## Проверки

Тесты используют стандартную библиотеку Python `unittest`; тесты обработчиков запускаются при установленной зависимости aiogram. Запуск: `python -m unittest discover -s tests`.

Синтаксис Python можно проверить стандартной библиотекой:

```sh
python -m compileall src
```

Для проверки Telegram-сценария нужны действительные credentials: `/report`, пропуск профиля, подтверждение, `/my_reports`, `/reports` и уведомления о смене статуса. Изменения БД должны проверяться на новой и существующей базе с сохранением имеющихся данных.

## Требования предметной области

Это согласованные требования будущего функционала, а не текущие возможности runtime:

- Заявки принимают текст, фото и видео. Настроенное место определяет доступные категории, а категория — обязательные и необязательные поля.
- Житель определяется Telegram-профилем. При первом создании заявки бот предлагает указать секцию, этаж и квартиру; каждое поле необязательное и пропускаемое.
- Житель создаёт заявки и видит все данные и историю статусов своих заявок.
- Ответственные настраиваются по домам в JSON и обрабатывают только назначенные дома. Администратор из `ADMIN_TELEGRAM_ID` может обрабатывать все дома.
- Содержание заявок доступно назначенным ответственным и администраторам.
- Ответственные получают уведомления о новых заявках, жители — об изменении статуса своих заявок.

При реализации незаполненных сценариев соблюдайте эти требования к доступу и приватности.

## Безопасность и развёртывание

Храните секреты и локальные параметры в окружении. `.env`, виртуальные окружения, кэш Python и файлы SQLite перечислены в `.gitignore`. Не коммитьте реальные токены, credentials, приватные ключи, производственные конфиги или базы. База содержит профильные сведения и данные обращений, поэтому защищайте файл БД и Telegram file ID как данные приложения.

Развёртывание — один постоянно работающий процесс long polling с окружением, JSON-конфигами и доступным для записи путём SQLite. FSM-состояние теряется при перезапуске. Docker, CI, webhook, менеджер процессов и резервное копирование не настроены.
