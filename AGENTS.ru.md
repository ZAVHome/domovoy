# Правила работы с репозиторием

## О проекте

«Домовой» — заготовка Telegram-бота для сбора обращений жителей по работе управляющей компании. Предполагаемый сценарий: житель начинает заявку в настроенной группе дома и продолжает в личном чате с ботом; контекст дома передаётся через deep link.

Сейчас реализован только каркас:

- При запуске загружаются переменные окружения и инициализируется схема SQLite.
- Команда `/report` в настроенной группе создаёт ссылку на личный чат с payload `report_<telegram_chat_id>`.
- `/start` распознаёт payload, находит дом в конфигурации и показывает адрес.
- Telegram ID начального администратора используется только для приветствия. Постоянная ролевая модель ещё не реализована.

Сбор профиля, мастер создания и сохранение заявок, приём медиа, роли, назначение ответственных, смена статусов и уведомления пока не реализованы. Тексты бота на русском, идентификаторы и комментарии в коде — на английском.

## Документация

- Ведите документацию проекта на русском и английском языках.
- Синхронизируйте русскую и английскую версии при каждом обновлении.

## Технологии

- Python 3.11 или новее.
- aiogram `>=3.32,<4`, long polling без webhook.
- python-dotenv `>=1.0,<2` для загрузки корневого `.env`.
- SQLite через стандартный модуль Python `sqlite3`.
- setuptools и структура пакета `src/`, настройка поиска пакетов находится в `pyproject.toml`.

В репозитории пока нет lock-файла, веб-фреймворка, внешней БД, системы миграций, очереди задач и контейнерной конфигурации.

## Структура и назначение модулей

- `pyproject.toml` — метаданные пакета, версия Python, зависимости и настройки setuptools.
- `src/domovoy/__main__.py` — точка входа: загружает настройки, инициализирует БД, создаёт `Bot` и `Dispatcher`, подключает router и запускает long polling. `settings` передаётся в `start_polling` для внедрения в обработчики.
- `src/domovoy/config.py` — неизменяемый dataclass `Settings`, пути проекта и `config/`, загрузка `.env`, проверка обязательных параметров, путь к БД и функция `load_json_config(name)`.
- `src/domovoy/database.py` — создание каталога БД и таблиц через `CREATE TABLE IF NOT EXISTS`. Схема включает `users`, `reports`, `report_fields`, `report_media`, `report_status_history`; миграций и функций доступа к данным пока нет.
- `src/domovoy/handlers.py` — общий aiogram `Router` и обработчики `/report` и `/start`. Конфигурация домов читается при вызове обработчиков.
- `src/domovoy/__init__.py` — только docstring пакета.
- `config/` — безопасные примеры JSON для домов, классификатора, статусов и ответственных.
- `.env.example` — шаблон переменных окружения.
- `README.md` и `README.ru.md` — синхронные инструкции на английском и русском.

## Установка и запуск

Работайте из корня репозитория:

```sh
python -m venv .venv
source .venv/bin/activate
pip install -e .
cp .env.example .env
```

Укажите в `.env` `BOT_TOKEN` и числовой `ADMIN_TELEGRAM_ID`. Замените пример ID группы и адрес в `config/houses.json`; остальные JSON-файлы настройте по необходимости. Добавьте бота в группу и запустите:

```sh
python -m domovoy
```

Команда `/report` в группе должна прислать ссылку на личный чат. Для реальной работы нужны действительные Telegram credentials и доступ к Telegram API.

`PROJECT_ROOT` вычисляется из `src/domovoy/config.py`, а `CONFIG_DIR` всегда указывает на `<корень проекта>/config`. `DATABASE_PATH` по умолчанию равен `./data/domovoy.sqlite3`; относительный путь считается от корня проекта. Инициализация создаёт каталоги и таблицы, но при запуске JSON-файлы домов, статусов, ответственных и ролей не загружаются в БД.

## Конфиги

Переменные окружения:

- `BOT_TOKEN` — обязателен; при отсутствии запуск завершается с `RuntimeError`.
- `ADMIN_TELEGRAM_ID` — обязателен, только десятичные цифры. Пока используется для приветствия администратора в `/start`, а не для выдачи роли в БД.
- `DATABASE_PATH` — необязательный путь к SQLite, по умолчанию `./data/domovoy.sqlite3`.

JSON:

- `config/houses.json` — массив `chats`; у каждой записи есть `telegram_chat_id`, `house_id`, `address`, `title`. Это единственный JSON, который сейчас читает runtime-код. ID должны совпадать с Telegram целиком, включая минус у групп.
- `config/classification.json` — `locations`, их `categories` и поля `fields` с ID, названием, типом и признаком обязательности. Пока не используется кодом.
- `config/statuses.json` — `statuses`, включая `initial` у стартового статуса. Пока не используется кодом.
- `config/responders.json` — `assignments`, сопоставление `house_id` и `telegram_user_ids`. Пока не используется кодом.

JSON загружается через `json.load` без проверки схемы, согласованности ссылок между файлами, кеширования или административного интерфейса.

## Стиль кода

Используйте четыре пробела, понятные имена модулей и функций, аннотации типов у публичных функций и настроек, `pathlib.Path` для путей и абсолютные импорты `domovoy.*`. Telegram-обработчики — асинхронные функции в общем `Router`. Пользовательские сообщения оставляйте на русском, если язык продукта намеренно не меняется.

JSON-примеры форматируйте двумя пробелами; используйте только вымышленные ID, адреса и токены. В `pyproject.toml` не настроены форматтер или линтер; не заявляйте, что конкретный инструмент обязателен, пока он не добавлен.

## Проверки

Тестов, каталога `tests/`, тестовых зависимостей и конфигурации тест-раннера сейчас нет. Не предполагайте наличие pytest или другого фреймворка.

Синтаксис Python можно проверить стандартной библиотекой:

```sh
python -m compileall src
```

Для проверки реального Telegram-сценария установите пакет и запустите `python -m domovoy`: `/report` в настроенной группе должен показать кнопку deep link, а `/start report_<chat_id>` — определить дом. При изменении обработчиков проверяйте также ненастроенную группу и некорректный payload. Изменения БД проверяйте на новой и уже существующей SQLite-базе: `IF NOT EXISTS` не выполняет миграции.

## Требования предметной области

Это согласованные требования будущего функционала, а не текущие возможности runtime:

- Заявки принимают текст, фото и видео. Настроенное место определяет доступные категории, а категория — обязательные и необязательные поля.
- Житель определяется Telegram-профилем. При первом обращении бот предлагает указать секцию, этаж и квартиру; каждое поле необязательное и пропускаемое.
- Житель создаёт заявки и видит все данные и историю статусов своих заявок.
- Ответственные обрабатывают назначенные заявки и меняют статус; администраторы управляют конфигурацией и назначают ответственных.
- Содержание заявок доступно назначенным ответственным и администраторам.
- Ответственные получают уведомления о новых заявках, жители — об изменении статуса своих заявок.

При реализации незаполненных сценариев соблюдайте эти требования к доступу и приватности.

## Безопасность и развёртывание

Храните секреты и локальные параметры в окружении. `.env`, виртуальные окружения, кэш Python и файлы SQLite перечислены в `.gitignore`. Не коммитьте реальные токены, credentials, приватные ключи, производственные конфиги или базы. База содержит профильные сведения и данные обращений, поэтому защищайте файл БД и Telegram file ID как данные приложения.

Развёртывание сейчас — один постоянно работающий процесс long polling с окружением, JSON-конфигами и доступным для записи путём SQLite. Не описывайте Docker, CI, webhook, менеджер процессов, резервное копирование и миграции как готовые возможности: в репозитории их нет.

## Коммиты и pull request

Репозиторий Git инициализирован на ветке `master`, но коммитов пока нет, поэтому принятую конвенцию коммитов подтвердить нельзя. Пока используйте короткие повелительные сообщения, например `Add configuration loader`. В pull request опишите изменение и его причину, перечислите выполненные проверки, приложите связанные задачи и скриншоты для визуальных изменений.
