# MVP текстовых заявок

## Цель

Подготовить первую рабочую версию сценария текстовой заявки Domovoy: от группового чата дома до просмотра заявки жителем и обработки ответственным.

## Объём и этапы

1. Проверять JSON домов, классификации, статусов и ответственных при запуске. Добавить версионированное изменение схемы SQLite с сохранением данных и слой операций с заявками.
2. Провести жителя через необязательные секцию, этаж и квартиру, настроенные места, категории и текстовые поля; поддержать отмену и подтверждение перед сохранением.
3. Дать жителю возможность просматривать только свои заявки, детали и историю статусов; ограничивать доступ по Telegram ID.
4. Уведомлять ответственных, назначенных дому; разрешить им обрабатывать заявки только этого дома по цепочке `new → in_progress → resolved → closed`. Администратору разрешить обрабатывать любые дома и выбирать любой статус. Уведомлять жителя об изменениях статуса.
5. Обновить документацию на русском и английском и добавить проверки стандартной библиотекой для хранения, доступа, конфигурации и миграции.

## Критерии готовности

- Подтверждённая заявка и начальная запись истории сохраняются в SQLite; черновик после отмены не сохраняется.
- Житель получает только свои заявки. Ответственный — заявки назначенных ему домов. Администратор — заявки всех домов.
- Необязательные поля профиля и заявки можно пропустить; обязательные поля заявки пропустить нельзя.
- Смена статуса обновляет заявку и добавляет запись истории. Ошибка отправки уведомления не отменяет сохранение заявки или статуса.
- При запуске конфигурационные ошибки и неверные связи между конфигами выявляются понятным образом; миграция сохраняет данные существующих пользователей.
- Автоматические проверки проходят. Перед развёртыванием дополнительно требуется проверка на реальном Telegram.

## Вне этого плана

Приём фото и видео, управление конфигурацией и назначениями из бота, сохранение незавершённого диалога после перезапуска процесса.
