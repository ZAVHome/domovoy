# Исправления по ревью: MVP текстовых заявок

## Результат

Исправлены все шесть замечаний из `review.ru.md`.

## Что изменено

1. **Постраничный просмотр:** списки жителя, ответственных и администратора загружаются страницами по десять заявок с навигацией к более новым и старым. При открытии заявки повторно проверяются права владельца или назначенного дома. Администратор просматривает все сохранённые дома.
2. **Лимиты сообщений Telegram:** длинные сводки, детали и уведомления ответственным разбиваются на сообщения не длиннее 3500 единиц UTF-16. Кнопки подтверждения и статусов остаются на коротких управляющих сообщениях. При ошибках Telegram при редактировании, включая неизменённое сообщение, обработчики не теряют сохранённые данные.
3. **Атомарная смена статуса:** SQLite обновляет заявку только при совпадении ожидаемого старого статуса и добавляет историю в той же транзакции. Устаревшее действие получает сообщение о конфликте и не может перезаписать новый статус.
4. **Атомарное и идемпотентное создание заявки:** заявка, динамические поля, начальная история и отметка профиля сохраняются одной транзакцией. Каждому мастеру выдаётся UUID-токен с уникальным индексом SQLite; повторное подтверждение возвращает уже созданную заявку, а не добавляет дубликат.
5. **Сохранение клавиатуры статусов:** после смены статуса короткое управляющее сообщение обновляется вместе с клавиатурой следующего действия. У ответственного остаётся следующий переход, у администратора — остальные статусы. Для закрытой заявки ответственный больше не получает кнопок перехода.
6. **Проверка конфигурации статусов:** при запуске теперь отклоняются отсутствующий, пустой или нестроковый заголовок, а также некорректный тип маркера `initial`. Проверки покрывают все три случая заголовка.
